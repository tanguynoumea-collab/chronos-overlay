<objective>
Créer le **point unique de normalisation des unités d'usage** (HDR-05) et y rapatrier **toutes** les
conversions existantes du dépôt.

Purpose: le projet fait circuler la même donnée sous **trois unités** (`utilization` 0..1 pour les
en-têtes `anthropic-ratelimit-unified-*`, `utilization` 0..100 pour `/api/oauth/usage`,
`used_percentage` 0..100 pour le pont statusLine) et `resets_at` sous **deux formats** (epoch secondes,
ISO 8601). La recherche a inventorié **12 sites de conversion répartis dans 4 fichiers** — chacun est un
point de divergence futur, et l'un d'eux (`resets_at: 9` servi comme un instant valide) est déjà un bug
constaté sur la machine de l'utilisateur.

Surtout, la phase 18 ouvre le **premier chemin texte → nombre du projet**, et c'est un piège vérifié
empiriquement : sous `fr-FR` (`InvariantGlobalization=false` est verrouillé par CLAUDE.md),
`double.Parse("0.63")` **lève** et `double.TryParse("0.63", out v)` rend **`false`** — une perte
**silencieuse**. Une sonde écrite « naturellement » ne planterait pas : elle serait simplement muette sur
la machine française, c'est-à-dire exactement la panne silencieuse que le milestone v1.5 éradique.
C'est la première chose à graver, **avant** d'écrire une seule ligne de lecture d'en-tête.

Output: `Services/UsageNormalization.cs`, deux fichiers de test (dont une garde de non-retour par
balayage de source) et 4 fichiers de production allégés de leurs conversions locales.

**Ce plan n'ajoute aucun provider et ne touche à aucun modèle** : `WindowState` est le plan 18-02, la
sonde est le plan 18-03.

public static double? FractionDepuisPourcentage(double? p0a100);     // 0..100 -> 0..1

Implémentation, règle par règle :

1. `FractionDepuisFraction` est la **porte de validation unique** : rend `f` si `f` est non null,
   non `NaN`, non infini et `>= 0.0` ; sinon `null`. **Ne clampe JAMAIS vers le haut** (commentaire
   obligatoire expliquant que `Exhausted` teste `>= 1.0` et qu'un dépassement doit rester visible) et
   **ne clampe JAMAIS vers le bas** (`null != 0`, doctrine du projet).
2. `FractionDepuisPourcentage(p)` = `FractionDepuisFraction(p is { } v ? v / 100.0 : null)`.
3. `FractionDepuisTexteFraction(valeur)` =
   `double.TryParse(valeur?.Trim(), NumberStyles.Float, CultureInfo.InvariantCulture, out var f)`
   puis `FractionDepuisFraction(f)` ; `false` -> `null`.
   **XML-doc obligatoire** citant le fait vérifié : sous fr-FR, `double.Parse("0.63")` lève et
   `double.TryParse("0.63", out v)` rend `false` — le point décimal des en-têtes HTTP n'est pas
   négociable, la culture de la machine si.
4. `InstantDepuisEpochSecondes(s)` : `null` si `s` est null ; sinon
   `try { var t = DateTimeOffset.FromUnixTimeSeconds(s.Value); return t < PlancherEpoch ? null : t; }
   catch (ArgumentOutOfRangeException) { return null; }`.
   **Commentaire obligatoire** : le cas RÉEL de cette machine est
   `{"five_hour":{"used_percentage":10,"resets_at":9}}` — janvier 1970 ne décrit rien, on rend
   l'inconnu plutôt qu'une géométrie fausse. 2020-01-01 est antérieur à l'existence des fenêtres
   d'usage Claude.
5. `InstantDepuisEpochMillisecondes(ms)` : même forme avec `FromUnixTimeMilliseconds`, **même
