## Sampling Rate

- **Après chaque commit de tâche :** la commande `<automated>` de la tâche (filtrée).
- **Après chaque plan :** suite complète + build Debug et Release à 0 avertissement.
- **Avant `/gsd:verify-work` :** build 0 avertissement (Debug + Release) et suite complète verte (porte finale = 42.2-10 tâche 2).
- **Latence max du retour :** ~60 s par tâche.
- Exécution SÉQUENTIELLE sur un seul arbre (pas de worktree), 01 → 02 → … → 10. Les tâches RED cassent volontairement la compilation
  du projet de test jusqu'à la GREEN du même plan ; aucun plan ne démarre tant que le précédent n'est pas vert.
- Interdits pendant toute la phase : écrire dans le vrai `~/.claude`, `%APPDATA%\Chronos` ou `shell:startup` (tous les tests
  travaillent sous `Path.GetTempPath()`, avec `Assert.StartsWith(Path.GetTempPath(), …)` dans les tests d'E/S, et des gardes de source
  interdisant `new SessionHookInstaller()`, `new ClaudeSettingsReconciler()`, `PasserelleReglagesClaude.ParDefaut()`, `new AutostartService()`,
  `new ArchiveStore()`, `new TreatedStore()` dans tests/) ; lancer l'exe ; cliquer l'overlay.
- Critère de succès 1, reformulé par l'orchestrateur (ZEUS, 2026-10-04) : « aucune réécriture qui perd l'original ». Règle différenciée :
  (1) fichiers propres à Chronos de faible risque (`settings.json`, `archived.json`, `treated.json`) — Illisible ⇒ quarantaine de l'original
  (`<nom>.illisible-<horodatage>.json`, même dossier, jamais supprimé) + incident + diagnostic, PUIS écriture normale ; quarantaine impossible ⇒
  blocage signalé ; Inaccessible (E/S passagère) ⇒ aucune écriture ni quarantaine, réessai ; (2) `~/.claude/settings.json` vide/illisible ⇒ jamais
  réécrit (plan 07) ; (3) agrégats / index (dérivés) ⇒ aucune écriture sur illisible (plans 04, 06).
- Pannes simulées : fichier tenu en `FileShare.None` (verrou), `FileShare.Read` (empêche le Move), `FileAccess.Read` + `FileShare.ReadWrite` sans
  `Delete` (lisible mais non renommable : quarantaine impossible), fichier vide, JSON tronqué, dossier
  « poison » (un fichier porte le nom du dossier), dossier portant le nom d'un shard (écriture d'index impossible).
