# Phase 42.2 Plan 02 : réglages qui ne perdent jamais l'original (quarantaine, Modifier, Save non levant) Summary

Désormais, `settings.json` n'est plus jamais écrasé sans que l'original soit conservé :
- **fichier illisible** (syntaxe, racine non objet, fichier vide) : il est renommé en `settings.illisible-<horodatage>.json` dans le même dossier, avec des octets identiques. Un incident est écrit dans `chronos.log` et apparaît au diagnostic. Ensuite seulement, l'écriture se fait, avec le marqueur `QuarantaineReglagesDepuis`.
- **erreur d'E/S passagère** : rien n'est écrit et rien n'est mis en quarantaine.
- **quarantaine impossible** : l'écriture est bloquée et le blocage est signalé.

Toutes les écritures passent par `SettingsService.Modifier`, sous verrou. `Save` ne lève plus jamais. Le widget de sessions n'écrit sa position qu'à la fin du glisser. Le diagnostic rapporte la lecture faite au démarrage, même si le fichier a été relu depuis.

## Ce qui a été fait

### Sécurité des données des tests (préalable)

- `OverlayWindowConfigTests` utilisait `ChronosPaths.Default()`, c'est-à-dire le vrai `%APPDATA%\Chronos`. Il utilise maintenant `MontageReglages.TempPaths()`. Cette migration a été commitée avant toute introduction de la quarantaine.
- La nouvelle garde `IsolationProfilTests` couvre tout `tests/Chronos.Tests` (hors `bin`/`obj`). Elle interdit :
  - `ChronosPaths.Default()` seul ;
  - `SpecialFolder.ApplicationData|UserProfile|Startup` ;
  - `GetEnvironmentVariable("APPDATA"|"USERPROFILE")` ;
  - `new SettingsService(ChronosPaths.Default()…` et toute API Write/Move/Delete/Copy appliquée à `Default()`.
- Elle se protège contre une exécution muette : elle doit voir plus de 50 sources, dont elle-même.

### `LectureReglages`

- Nouvelle issue `Inaccessible`.
- Nouveau champ `Cause` (« Type : message », « fichier vide », « racine non objet »).
- Nouvelle propriété `EstFiable`, vraie pour Absent, Lu et LuAvecRetombees.

### `SettingsService`

- **Verrou unique** sur Load, Modifier, Save et ChargerPourDemarrage.
- **Load** :
  - fait 5 essais de lecture espacés de 10 ms sur IOException ou UnauthorizedAccessException ; au-delà, l'issue est Inaccessible ;
  - un fichier vide ou blanc donne Illisible ;
  - la lecture valeur par valeur (SOC-01) est inchangée ;
  - Load n'écrit et ne renomme jamais rien ;
  - chaque issue non fiable est comptée.
- **Quarantaine** :
  - elle utilise `File.Move(…, overwrite: false)` vers `settings.illisible-yyyyMMdd-HHmmss[-n].json` (jusqu'à 100 suffixes) ;
  - un succès incrémente le compteur, renseigne `DerniereQuarantaine` et écrit l'incident « … mis en quarantaine sous … » ;
  - un échec produit le refus « quarantaine impossible — … — settings.json n'est pas réécrit ».
- **Modifier(mutation)** :
  - lit le fichier puis appelle `PreparerEcriture` ;
  - après une quarantaine, le marqueur est ajouté aux valeurs lues, puis la mutation est appliquée ;
  - l'écriture n'a lieu que si `PreparerEcriture` l'autorise ;
  - rend toujours la valeur produite par la mutation.
- **Save** rend un `bool` et ne lève jamais (`catch (Exception)` englobant). Il suit la même règle que Modifier.
- **Ecrire** :
  - un contenu identique au disque n'est pas réécrit ;
  - il écrit dans un temporaire unique `.tmp-<pid>-<guid>`, puis fait le Move en 5 essais espacés de 20 ms ;
  - en cas d'échec, le temporaire est supprimé et le refus est enregistré ;
  - en cas de succès, `DerniereEcritureRefusee` repasse à null.

### Sites d'écriture

- `OverlayController` : accroche, `SendToBackground`, `BringToForeground`.
- `ReglagesHistoriqueSurDisque.Modifier`.

- `SessionsWindow.DeplacementTermine` est déclenché au retour de `DragMove`. L'`InvalidOperationException` levée quand le bouton est déjà relâché est absorbée.

### Diagnostic et démarrage

- `DiagnosticService` relève, avant tout `await`, `LectureDuDemarrage ?? DerniereLecture` et les compteurs. Il ajoute, selon le cas, trois sous-lignes : « lectures non abouties depuis le démarrage : N (dernière : …) », « QUARANTAINE : … conservé sous <nom> » et « ÉCRITURE BLOQUÉE : <cause> ».
- `App.xaml.cs` : le singleton `ChronosSettings` est obtenu par `ChargerPourDemarrage()`.
