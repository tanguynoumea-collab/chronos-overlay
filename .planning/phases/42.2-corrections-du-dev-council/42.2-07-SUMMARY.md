# Phase 42.2 Plan 07 : une seule passerelle, prudente, vers ~/.claude/settings.json Summary

`~/.claude/settings.json` n'a plus qu'un écrivain : `PasserelleReglagesClaude`. L'installateur de hooks et le réconciliateur passent tous deux par elle. Dans les cas suivants, rien n'est écrit et la cause est rendue :
- fichier existant mais vide, blanc ou invalide ;
- fichier verrouillé ;
- fichier modifié ou apparu entre la lecture et l'écriture ;
- lien symbolique ;
- sauvegarde impossible.

Deux autres situations ne retirent plus les hooks :
- des réglages Chronos illisibles au démarrage : les hooks sont laissés tels quels (MAT-5) ;
- une quarantaine des réglages : aucun hook n'est retiré tant que l'utilisateur n'a pas choisi sur le widget.

## Ce qui a été fait

### Tâche 1

**`ClaudeSettingsJson.ParseOrNull`**
- `null` (fichier absent) donne un objet vide.
- Une chaîne vide ou blanche donne `null`, comme tout contenu inexploitable (DATA-4).
- Les docs (b) et la doc de la méthode sont à jour.

**`PasserelleReglagesClaude`** (type neutre, ne lève jamais)
- `Lire()` :
  - fait 3 essais espacés de 20 ms sur IOException ou UnauthorizedAccessException ;
  - relève mtime UTC et taille avant le texte ;
  - un contenu vide donne `Inexploitable` avec la cause « fichier vide », un JSON invalide la cause « JSON inexploitable ».
- `Ecrire(lecture, texte, creerSiAbsent)` refuse dans cet ordre : lecture inexploitable, absent sans création, `ReparsePoint` (« lien symbolique — Chronos n'écrit pas au travers »), sauvegarde impossible.
- Sauvegarde : le texte lu est écrit dans `claude-settings-yyyyMMdd-HHmmss[-N].json`, rétention 5.
- Le temporaire porte le pid et un Guid.
- Juste avant le `File.Move`, le fichier est recontrôlé : un fichier absent doit l'être encore, un fichier lu doit avoir les mêmes mtime et taille. Sinon : refus « modifié entre lecture et écriture » et le temporaire est supprimé.

### Tâche 2

**`SessionHookInstaller`**
- Constructeur `(PasserelleReglagesClaude)`, plus un constructeur de compatibilité `(string?)`.
- `Install` et `Uninstall` rendent un `EcritureReglagesClaude` :
  - un fichier illisible est refusé ;
  - un fichier déjà conforme donne « déjà conforme », comparé sur la forme normalisée ;
  - sinon l'écriture passe par `_passerelle.Ecrire` (`creerSiAbsent` vaut true pour Install, false pour Uninstall).
- `WriteAtomic` et `IsInstalled` sont supprimés (PERT-5).

**`ClaudeSettingsReconciler`**
- Constructeur `(PasserelleReglagesClaude, exePath?)`. Le constructeur à trois chemins est conservé.
- `ReconcileJson` reçoit `bool? hooksWanted` et `bool conserverHooks = false` en fin de signature, après le `out` :
  - `null` : aucun `ApplyHooks`, la barre est quand même retirée ;
  - `false` avec le marqueur : aucune purge. Si des groupes Chronos existent, ils sont repointés vers l'exe courant ; sinon rien n'est ajouté.
- `Reconcile(bool?, commandeHeritee, conserverHooks, quarantaineDepuis)` passe par la passerelle.
- `BilanReconciliation` gagne `HooksLaissesTelsQuels` et `HooksConservesDepuis`.
- `Sauvegarder`, `CibleDeSauvegarde` et `WriteAtomic` sont supprimés. Nouveau paragraphe (e) dans la doc, et (d) mis à jour.

**`App.xaml.cs`**
- Une passerelle DI unique, `PasserelleReglagesClaude.ParDefaut()`, partagée par les deux services.
- `hooksVoulus` vaut null quand `LectureDuDemarrage` n'est pas fiable.
- Le marqueur est passé à `Reconcile`.

**`SessionsController`**
- Enable active toujours le widget. Si les hooks sont refusés, le MessageBox d'activation ajoute « Hooks non installés : {cause} — ~/.claude/settings.json n'a pas été modifié. ».
- Disable appelle `Uninstall()` sans try (il ne lève plus).
- Les deux choix posent `QuarantaineReglagesDepuis = null`.

**`DiagnosticService`**
- Section « [Réglages de Claude Code] » : les deux nouvelles lignes.
- La ligne de quarantaine lit le réglage `s` lui-même.

## Deviations from Plan

### Adaptations de tests existants (demandées par le plan)

- `ClaudeSettingsJsonTests.ParseOrNull_sur_fichier_absent_donne_un_objet_vide` ne garde que le cas `null`. La partie « "   " » est passée dans le nouveau `ParseOrNull_sur_contenu_vide_ou_blanc_rend_null` (Theory : "", "   ", "\n  \n").
- `SessionsTests.IsInstalled_est_faux_quand_le_groupe_pointe_une_autre_version` est supprimé (PERT-5).
- `ClaudeSettingsReconcilerTests.Un_fichier_illisible_n_est_pas_touche_et_le_bilan_le_dit` vérifie maintenant le préfixe « illisible — rien écrit », puisque la cause de la passerelle suit (voir decisions).
- **Sauvegarde = texte lu, et non plus copie disque.** Les tests existants qui comparent la sauvegarde aux octets de l'original restent verts, car les témoins sont écrits par `File.WriteAllText` (UTF-8 sans BOM). Limite connue : un original avec BOM aurait une sauvegarde sans BOM, au contenu textuel identique.
- **`Install` ne rend plus void.** `PrudencesEcritureHooksTests` l'appelle en instruction et ignore le résultat : aucune modification n'a été nécessaire.
